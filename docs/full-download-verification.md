# フル尺取得の検証

2026-10-26、v0.1.1（versionCode 2）のJavaScript拡張で確認しました。

## 確認できたこと

1. 変更していない本家の拡張SDK（5b8754d5eeeb5755aa7095744239910ffc2de8db）のRhino 1.8.1で `download-source` を実行。
2. 拡張が `myspoti.http` だけで検索・匿名セッション作成・音源URLの解決・先頭と末尾の疎通確認を行い、標準のM4A候補を返すことを確認。
3. そのSDKが返したURLとUser-Agentを使い、PCの検証用取得処理で音源全体を保存。Node.jsはこの検証処理にだけ使い、拡張の実行・URL解決には使っていません。独自APIサーバーも使用していません。
4. Content-Length相当の候補サイズと保存バイト数を照合し、ffprobeで音声形式・長さを確認。
5. ffmpegの `-xerror` を指定し、先頭から最後までデコードして正常終了を確認。

Pretenderは本家ダウンローダーと同じ4 MiB単位のRange要求を2回行い、結合した全体を検査しました。各応答のサイズも要求範囲と一致しました。

## 修正内容

初期版の単純なiOS player要求を、公開APIのvisitor_idから得る匿名セッションを使ったVISIONOSクライアントの要求へ変更しました。再生要求のcpnを音源URLにも渡し、必要なクライアント情報・ヘッダー・要求パラメーターを揃えています。NewPipeExtractorとyt-dlpの公開実装を参考にしています。これらの差を個別に取り除く比較はしていないため、「403の原因は特定の一項目だった」とは断定しません。

先頭だけ成功するケースを除外するため、候補を返す前に末尾512バイトの取得も確認します。Cookie・ログイン・外部サーバー・ネイティブブリッジ・動的JavaScript実行は使っていません。

## 未確認・制限

- Android実機のMyspoti画面からのインストール、保存、暗号化、再生はまだ確認していません。SDKでのURL解決とPCでの全体取得の検証です。
- 網羅的な取得率の検証ではありません。「夜に駆ける」は今回の厳格なメタデータ照合で候補を返せませんでした。取得先に存在しないと証明したわけではありません。
- 音声プレビューとの録音比較は行っていません。形式・長さ・全デコードの成功だけでは、Spotifyと同一録音である保証にはなりません。isrcMatchedはfalseです。
- YouTube側の変更や地域・接続環境により、同じ結果になるとは限りません。
- YouTube.jsのライブラリ全体やyt-dlpは組み込んでいません。小さな同期JavaScriptで本家の標準拡張APIを使用しています。
- 音源ファイル、期限付き音源URL、visitor情報はリポジトリや配布ZIPに含めていません。
